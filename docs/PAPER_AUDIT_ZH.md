# MUJICA 原文与当前实现审查

日期：2026-09-15。对象仅为本目录 `MUJICA_HIMLoco_Go2W_PPO/mujica_himloco_go2w`。
依据 [arXiv v1 原文](https://arxiv.org/html/2605.13058v1) 的 Fig.2、III-B/C、IV-A/D、V-A 和 Table II/III，
同时阅读当前模型、优化器、runner、环境和电机实现。本轮审查没有运行仿真或训练。

## 结论

当前实现保留了 MUJICA 的主要结构：带技能标记的共享底层策略、历史状态估计、非对称价值网络、
冻结底层后的高层技能选择。其组织方式与原文框架一致。[原文 Fig.2、IV-A/D](https://arxiv.org/html/2605.13058v1#S4)

适合将本项目描述为 **MUJICA 结构上的 PPO 与三类地形适配版**。除用户明确选择的 PPO、任务和奖励调整外，
电机参数、随机化、估计器训练细节等仍有工程选择，不能称为作者参数的完整复现。

## 当前代码中的完整数据链

```text
实际地形 task_ids → S1 技能标量 → 6×58 本体历史
  → 历史 MLP → 持续 GRU → 速度3、碰撞18、轮地距离4、latent16
  → 当前帧58 + 估计特征41 → 一个共享 actor → 16维动作
  → 12个腿位置目标 + 4个轮速度目标 → PD → 电机限幅 → 仿真

特权观测270 → reward critic → PPO
当前真实速度/碰撞/轮地距离 → 估计器监督
真实下一帧 → reference encoder → SwAV

S2：冻结整个底层 → 去掉技能标量的6×57历史 → 分类选择器
  → 写入新技能标量 → 冻结底层输出动作 → 速度跟踪回报
```

| 代码部分 | 源码观察与判断 |
|---|---|
| `models.py:MultiSkillActorCritic` | 三个任务使用同一个 actor、estimator 和 reward critic；技能标量参与观测，没有独立专家头或蒸馏流程 |
| `models.py:StateEstimator` | 输出速度、碰撞概率、轮地距离和 latent；使用速度/距离 MSE、碰撞 BCE 与 SwAV |
| `runner.py:learn` | 估计监督取当前状态，reference 取真实下一帧；超时使用真正终态，不把自动重置后的新状态当成终态 |
| `models.py:SelectorActorCritic` | 选择器输入移除每帧技能通道，输出三类分布；actor 没有直接读到特权地形高度 |
| `runner.py` 的 S2 初始化 | 整个底层设为不求梯度并切到推理模式，选择器训练不会更新估计器或底层 actor |
| `export.py:DeploymentPolicy` | 导出实际 actor、在线估计器和选择器；不带 critic 或参考编码器；推理保留显式 GRU 状态 |

以上是结构及源码数据路径判断，不能代替运行、收敛或运动能力验收。

## 除 PPO 替换外，需要明确的实现选择

### 1. 电机模型未校准

当前 `motor.py` 根据 URDF 的 effort/velocity、固定速度拐点和小腿角度余弦因子构造对称力矩包络。
`calibrated=false`，URDF 速度限值被当成包络速度上限，尚未用实测曲线或电机手册拟合。
因此保留了随速度/位置变化的限幅机制，但不能确认与原文电机可行域数值相同。

`violation_count` 仅作诊断。普通 PPO 中没有约束 critic、约束 advantage 或成本阈值优化；
执行端限幅与学习过程中的约束优化是不同机制。这属于选择普通 PPO 后的明确边界。

### 2. 估计器采用一步截断的训练方式

`StateEstimator.loss()` 对采样时的 hidden 做 detach；`storage.py` 将 rollout 展平并打乱训练，
所以 GRU 在采样时持续记忆，但训练只从当前一步反传，未按整段时间序列展开。

`ppo.py` 对 rollout 保存的估计特征进行 PPO 更新，估计器由独立优化器更新。
这样 PPO 的比率和 KL 只覆盖给定特征下的 actor 变化，不包含估计器变化引起的整个策略变化。
原文未给出足以核实这一截断长度、梯度边界和优化器组织的细节，应将其标为工程补全，而非已确认相同。

### 3. 网络尺寸和估计标签有明确工程约定

当前使用 GRU64、latent16、32 个原型及配置文件中的 MLP 层宽；SwAV 温度为 3.0。
这些参数保存在 `configs/mujica_default.json` 和模型默认配置中，不能仅凭结构图认定它们是作者配置。

19 个实际刚体通过合并两个头部接触通道得到 18 组标签；接触阈值为 1N。
轮地距离使用轮心下方的高度场采样减去轮半径，倾斜轮子和台阶立面处存在几何近似。
这些定义会影响估计器监督质量，本轮没有更改或运行验证。

### 4. 域随机化仍是 HIMLoco 配置

当前摩擦统一采样 `[0.25,1.25]` 并写入静/动摩擦；Kp/Kd 倍率为 `[0.9,1.1]`。
外力在每 8 个控制步的下一物理步施加一次 `[-30,30]N` 短脉冲；速度扰动间隔 15 秒。
这些设置与原文 Table II 不同。例如原文的外力间隔为 2–3 秒，速度扰动间隔为 8–12 秒。
不能仅根据间隔比较强弱，还要考虑力持续时间与施加坐标系。[原文 Table II](https://arxiv.org/html/2605.13058v1#S5.T2)

这些配置可以作为当前实验的基线，但应单独记录；本轮没有在奖励修改中顺带更换随机化方案。

### 5. PD 符号按当前状态定义保持负反馈

当前控制为 `Kp*(q_target-q)-Kd*qdot` 和 `Kd*(wheel_target-qdot)`。
原文 Eq.4 与 Fig.2 中的符号写法并不完全一致；不能只对照排版公式修改当前正确的负反馈方向。
动作缩放和真实关节轴仍需用户自行做物理方向检查。

## 用户主动调整的部分

当前三个任务是平地及坡道、离散障碍、上下楼梯，场景和课程由 `terrain.py` 提供；
三类任务均衡采样，S1/S2 统一正立重置与机身碰撞终止。
最新奖励在共用 15 项基础上放宽复杂地形姿态，见 [REWARDS_ZH.md](REWARDS_ZH.md)。

原文 Table III 中共享奖励的对照还同时移除了技能标记，且包含不同目标的任务。
不能用那个结果直接否定当前保留技能标记、共用地形行走目标的方案。[原文 V-C](https://arxiv.org/html/2605.13058v1#S5.SS3)

对当前新任务的推断：离散障碍和楼梯的目标相近，两个技能可能学出重叠行为。
这不说明代码缺少某个模块；技能条件是否有用、S2 是否带来收益，需要看用户后续训练和交叉播放结果。
